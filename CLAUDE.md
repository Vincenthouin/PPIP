# PPIP — PI Production Planner

Interactive dashboard for product designers in agile environments. Manages workload across PIs (Program Increments) split into sprints, computing effective production time from PI dates, sprint config, and customizable meeting categories.

## Stack

- React 18 + TypeScript
- Vite 6 (dev/build) — see [vite.config.ts](vite.config.ts) for the `@` → `src/` alias and the `figma:asset/` resolver
- Tailwind CSS 4 (via `@tailwindcss/vite`)
- shadcn-style UI components in [src/app/components/ui/](src/app/components/ui/) (Radix primitives + class-variance-authority)
- react-dnd (HTML5 backend) for the template → sprint drag-and-drop
- Supabase (auth + admin role + edge function backend) — sign-up restricted to `@somfy.com` emails
- recharts for the production summary
- Persistence: Supabase Postgres (workspace tables — see [supabase/migrations/](supabase/migrations/)). UI-only prefs (active PI/product/user) still in `localStorage` under `pi-planner:ui-prefs:v1`.
- Realtime sync: Supabase Realtime channel `workspace` subscribed to every workspace table — edits propagate live across clients.

## Scripts

```bash
npm i           # install
npm run dev     # vite dev server (default http://localhost:5173)
npm run build   # production build to dist/
```

No lint, test, or typecheck script is wired up.

## High-level architecture

Three views switched in [src/app/App.tsx](src/app/App.tsx): `landing` | `dashboard` | `admin`.

1. **Auth gate** ([src/app/auth/auth-gate.tsx](src/app/auth/auth-gate.tsx)) — Supabase auth, `@somfy.com` allowlist. Calls the edge function `make-server-3775ce8a` for signup / role management.
2. **Landing view** — global PI selector + product grid. New products auto-create a matching tag.
3. **Product dashboard** — for a chosen `(productId × piId)` board: PI header, user bar, template library (left), sprint board (right), production summary chart.
4. **Admin dashboard** — user role management; only visible to users with `role === "admin"`.

## Data model (see [src/app/components/pi-types.ts](src/app/components/pi-types.ts))

- **PI** — global time unit shared across all products (custom calendar).
- **Product** — global; each product owns one auto-created tag.
- **Tag** — global; can be product-tags (auto, deleting product cascades) or standalone (user-created from the template editor).
- **CategoryTemplate** — global, shareable across products/PIs, taggable via `tagIds`.
- **Board** — scoped by `boardKey(productId, piId)`; holds `categories` (assignments per sprint) and `preselectedIds`.
- **Workspace** — the root state: `{ pis, products, tags, templates, boards, users, activeProductId, activePiId, ... }`.

All writes go through [src/app/components/workspace-store.ts](src/app/components/workspace-store.ts) — `useWorkspace()` loads from Postgres on mount, subscribes to Realtime, applies optimistic local updates, then writes via the Supabase JS client. Cascade deletes are enforced by FKs in the schema, not by the client.

## Backend

Supabase edge function at [supabase/functions/server/](supabase/functions/server/) provides `/signup`, `/me`, `/users`, `/users/:id/role`, `/users/:id` (DELETE). Roles live in the `user_roles` table (`admin` | `editor` | `viewer`). The function still uses the `kv_store_3775ce8a` table for the admin-bootstrap one-shot flag (`bootstrap:admin_v1`). `charlotte.lopez@somfy.com` is the seed admin and the bootstrap re-asserts her admin role on every health/signup call.

Supabase project ref + anon key live in [utils/supabase/info.ts](utils/supabase/info.ts) (autogenerated, safe to commit — anon key only).

## Conventions

- UI components are shadcn-style: use the existing primitives under [src/app/components/ui/](src/app/components/ui/) before adding new ones. `cn()` from [src/app/components/ui/utils.ts](src/app/components/ui/utils.ts) is the className combiner.
- When a UI primitive exports a CVA variants object (e.g. `buttonVariants`), it must be exported alongside the component — `pagination.tsx`, `alert-dialog.tsx`, and `calendar.tsx` all import `buttonVariants` from [button.tsx](src/app/components/ui/button.tsx).
- The workspace store is the single source of truth for in-app state. Don't read/write `localStorage` directly from components.
- The v1 → v2 migration in [workspace-store.ts](src/app/components/workspace-store.ts) means schema changes need a new versioned key + migration step.
- Imports use the path alias `@/` for `src/` (configured in [vite.config.ts](vite.config.ts)).
- Drag-and-drop is HTML5Backend only; the `DndProvider` lives in the dashboard view in [App.tsx](src/app/App.tsx).
